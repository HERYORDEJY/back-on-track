# D3 learner loop

Prepared before implementation on 2026-10-06. D2's engine, service, live AI budget, cache replay and thin browser path are verified. This milestone adds the online learner loop; service-worker snapshots, queued offline mutations and performance/accessibility hardening remain D5. Advisor transparency and deletion remain D4. No new dependency, schema, threshold or persona change is planned.

1. Define a shared learner view contract in `lib/types.ts`. Services provide session status/editability, localized dates, the featured and weekly sessions, counts, reminders, plan age and change summary. Components render these values without calculating scheduling or simulated dates.
2. Run the documented learner UI and re-plan logic threads in separate worktrees. The UI thread owns learner pages/components and both message files; the logic thread owns plan/check-in services, session routes and engine/service tests. The main thread owns student updates, shared contracts/header/read-aloud/styles, documentation and integration.
3. Add a strict student PATCH service/API for language, optional bounded goal/context, weekday minutes and variable hours. Hour changes invalidate the current plan; the intake immediately builds a replacement using the previous version for the change summary. Language changes preserve the plan and use the student's saved language throughout the learner header.
4. Add atomic today-only done/missed check-ins with completion provenance, idempotent repeated actions, safe reversal and locked earlier/future/stale sessions. On a visit starting tomorrow, re-plan for an effectively missed session; today's missed session stays editable. Re-plan after expired infeasible focus dates. Record the separate delayed offline first-check-in decision for D5.
5. Build the prefilled intake, individual weekday minutes and average-hours mode, editable hours, tonight's actions, the calendar week's sessions, change/weekly-hours banners, reminders, topic facts/counts, workload display and the full honest infeasible next step. Read aloud the session plus summary or infeasible summary plus next step. Use both language files and retain published English titles.
6. Verify meaningful intake/API/check-in/provenance/re-plan tests, all persona paths, both languages at 375/1280 px, voice controls and the reset. Run `npm run check` and `npm run build`. Update affected docs/status and `CODEX_LOG.md`; close the milestone with one D3 commit using a subject and bullet body.

Design plan: retain canvas #f6f8fc, ink #13213a, secondary #475973, action #315fcb, positive #1a705d and divider #d8e3f5. Use the existing system font, left alignment and readable line lengths. Make tonight's session the prominent actionable region; keep the week as a compact list and topic facts as expandable details. Intake weekday inputs form a simple two-column grid on a phone. Existing repeated summary cards are reduced in favor of the student's actual sequence: goal → tonight → week → warnings → course decisions → counts/workload. This uses study time as the organising structure and adds no decorative imagery or motion.

The maintainer chose next-day re-planning for a missed session on 2026-10-06. Delayed first offline check-in handling remains a D5 decision. The privacy cache-deletion decision belongs to D4.
